Part 07

Evaluation & Results

Evaluation Design

Coverage

Line, branch & endpoint coverage of the API under test.

Mutation detection

Share of injected faults the suite kills (test strength).

Execution validity

Share of generated tests that compile & run correctly.

All five configurations run on the same backend & BA document, under identical conditions — so differences reflect the architecture, not the inputs.

Key Findings

① Context wins

RAG grounds tests in real documentation → higher relevance & coverage than standalone LLM.

② Hybrid = reliability

Rule-based validation + static analysis lift execution validity to 96%.

③ Adaptation helps

LoRA improves domain understanding; with RAG it tops every metric.

④ Scale & speed

AI explores far more input/boundary scenarios automatically than manual design.

Part 08

Limitations

Scope & Boundaries

01 · Research scope

Prototype scale vs. large distributed enterprises with hundreds of services.

02 · Input dependency

Output quality bound by completeness & clarity of requirement artefacts.

03 · Model variability

Generative non-determinism; compute cost of LoRA & Hybrid configurations.

04 · Testing scope

Backend API & integration testing — not UI, performance or security testing.

Part 09

Conclusion & Contributions

Conclusion

Generative AI — especially retrieval + domain adaptation — measurably improves automated test generation for enterprise backends: higher coverage, stronger defect detection & more valid tests.

Conceptual — a modular AI-augmented testing framework.
Methodological — first like-for-like comparison of 5 AI configs.
Empirical — coverage + mutation + execution validity evidence.
Practical — embeddable .NET prototype with CI/CD.
